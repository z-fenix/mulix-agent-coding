# Feature Specification: P2 生态——子代理编排、自定义工具与记忆服务

**Change**: `002-p2`

**Created**: 2026-10-08

**Status**: Draft

**Input**: User description: "进入 P2"（design §11 路线图 P2 行：自定义工具框架完善、子代理编排、skills、记忆服务、CLAUDE.md 管理命令、分层检查工具、用户自定义钩子开放）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 子代理完成多步编码任务 (Priority: P1)

用户在 mulix 会话中把一项可分解的工作（如「把这三个包的测试补齐」）交给子代理：主代理创建子任务、委派、子代理在真实仓库独立完成多步工作（读写文件、跑测试、提交），结果与产物回收进主会话。子代理的每次工具调用走与主代理相同的权限治理（审批/策略），其 usage 计入同一会话账本。

**Why this priority**: 这是 design §11 P2 的核心出口标准（「子代理任务在真实仓库完成多步编码任务」），也是 P2 其余能力（记忆、skills）的最大消费方。

**Independent Test**: 在带真实任务的仓库中发起一次委派，观察子代理回合完成且结果回收、权限审批与 usage 记账正常。

**Acceptance Scenarios**:

1. **Given** 一个工作区中的编码任务，**When** 用户（或主代理）创建子代理并委派任务，**Then** 子代理在自己的会话中完成多步工作，结果与最终消息回收至主会话，镜像中可审计子代理的回合与工具调用。
2. **Given** 子代理请求一个未被 allow 的工具，**When** 处于 attended 会话，**Then** 审批卡出现在用户面前（与主代理同一治理回路）；无人值守时 fail-closed 拒绝。
3. **Given** 子代理运行中，**When** 用户在主会话执行取消，**Then** 子代理回合被收口（不悬挂），其已发生的 usage 仍入账。

### User Story 2 - 记忆召回（可开关） (Priority: P2)

用户开启记忆服务后，每回合提交前系统从本地记忆库检索相关记忆（如项目约定、既往决策），命中内容以低权限文本块追加在该回合 user message 尾部——不改变系统提示、不改变工具清单（缓存构造护栏不破坏）。用户可随时关闭，关闭后行为与 P1 完全一致。

**Why this priority**: 直接提升跨会话连续性，但依赖面（索引质量、护栏）需要子代理编排先行验证注入点，故排在子代理之后。

**Independent Test**: 开启记忆后发起回合，观察到召回块出现在回合尾部且 Boot 面逐字节不变；关闭后回合与 P1 行为一致。

**Acceptance Scenarios**:

1. **Given** 记忆库中已有若干条记忆，**When** 用户提交一回合与某条记忆语义相关的输入，**Then** 该记忆（BM25 检索命中）以低权限文本块出现在该回合 user message 尾部，且两次启动的配置逐字节一致（缓存护栏测试不回归）。
2. **Given** 记忆功能关闭（默认），**When** 用户提交回合，**Then** 无任何召回注入，行为与 P1 一致。
3. **Given** 用户在会话中说「记住：本项目用 pnpm」，**When** 回合完成，**Then** 该条记忆被持久化，后续会话可检索命中。

### User Story 3 - 用户自定义 MCP server 与工具命名空间 (Priority: P2)

用户在项目 mulix.toml 声明外部 MCP server（command 形式），mulix 启动时接入：工具以「server 名」命名空间暴露给引擎（无跨 server 命名冲突），单个工具调用有超时上限（不悬挂），外部 server 崩溃不拖垮 mulix 主进程（降级 + 告警）。

**Why this priority**: 打通「自定义工具框架完善」中最常被请求的能力（P1 只有内置 registry）；与内置工具共用权限治理与审计。

**Independent Test**: 配置一个返回固定结果的外部 echo MCP server，回合中调用其工具成功、超时被收口、server 被杀后主进程存活并告警。

**Acceptance Scenarios**:

1. **Given** mulix.toml 声明一个外部 MCP server，**When** 会话启动，**Then** 该 server 的工具以命名空间形式进入引擎工具面（注册期冻结，两次启动逐字节一致），调用结果正确返回。
2. **Given** 外部工具调用超过超时上限，**When** 超时触发，**Then** 该调用以超时错误收口，回合不悬挂，事件留痕。
3. **Given** 外部 server 进程在会话中途退出，**When** 下一次调用该 server 工具，**Then** 得到明确错误应答，mulix 主进程与其他工具不受影响。

### User Story 4 - 项目指令管理与变更提醒 (Priority: P2)

用户通过 mulix 管理项目指令文件（CLAUDE.md/AGENTS.md）：提供管理命令查看当前生效的指令快照；会话运行中若这些文件被修改，用户收到提醒事件（不重载、不破坏会话——P1 快照语义保持）。

**Why this priority**: 补齐 FR-008 的 P2 半部（watcher），是小而独立的能力，与缓存护栏强相关（只提醒不重载）。

**Independent Test**: 会话运行中修改 CLAUDE.md，观察到提醒事件出现在镜像与前端，且会话继续使用启动快照。

**Acceptance Scenarios**:

1. **Given** 会话运行中，**When** 项目 CLAUDE.md 被外部修改，**Then** 用户收到一条提醒事件（内容含变更文件与「下会话生效」语义），镜像可审计，会话不中断。
2. **Given** 用户查询当前指令快照，**When** 执行管理命令，**Then** 输出启动时快照的来源文件与内容摘要。

### User Story 5 - 分层检查工具与用户自定义钩子 (Priority: P3)

分层规则（分层导入、文件职责棘轮、第二 system prompt 路径）从「review 约定 + 少量测试」落地为 CI 可执行的检查工具，违规即 CI 阻断；用户可在 mulix.toml 声明自定义钩子（在 P1 内置钩子消费者之外追加自己的回调脚本），经同一 hook 分发通路执行。

**Why this priority**: 工程治理价值高但不直接产出用户可见功能；放在子代理/记忆/自定义工具稳定之后。

**Independent Test**: 制造一处分层违规，检查工具报错且 exit 非零；配置一个自定义 PreToolUse 钩子脚本，观察其在对应时点被执行且输出入审计。

**Acceptance Scenarios**:

1. **Given** 代码中出现违反分层规则的 import（如 utility leaf 引用内核包），**When** 运行分层检查工具，**Then** 报告违规位置并以非零退出码失败。
2. **Given** 用户声明了一个自定义钩子脚本，**When** 对应钩子时点触发，**Then** 脚本被执行（stdin 收到事件 JSON），其退出码与输出按钩子语义生效并留痕。
3. **Given** 自定义钩子脚本崩溃或超时，**When** 触发时点到达，**Then** 主流程按 fail-open/fail-closed 的既定语义继续（不悬挂、有告警）。

---

### Edge Cases

- 子代理委派链中出现循环委派（A 委派 B、B 又委派 A）时怎么办？——必须有委派深度上限，超限拒绝并留痕。
- 记忆召回命中 0 条 / 命中过多（超过注入预算）时怎么办？——0 条静默跳过；超预算按相关性截断到上限（上限为配置项，默认值见 Assumptions）。
- 外部 MCP server 输出违反协议（畸形 JSON、缺失字段）时怎么办？——以工具错误应答收口，不崩溃主进程。
- 会话中指令文件被删除（而非修改）时怎么办？——与修改同等对待：提醒事件，快照不回滚。
- 自定义钩子声明了不存在的时点/路径时怎么办？——启动期校验拒绝（fail-fast），不静默忽略。
- 同名外部 server 与内置 server 冲突时怎么办？——启动期拒绝并报错（内置名保留）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-101**: mulix MUST 支持在会话内创建子代理并委派任务：子代理拥有独立会话镜像（可审计回合与工具调用），其工具调用经与主代理相同的权限治理回路（策略/审批/超时 fail-closed）。
- **FR-102**: 子代理的委派结果 MUST 回收至主会话：最终消息、退出原因与 usage（token/成本）计入主会话账本，镜像保留委派链（谁委派了谁）。
- **FR-103**: mulix MUST 限制委派深度（默认上限 3 层）与并发子代理数（默认上限 4 个），超限请求以明确错误拒绝并留痕。
- **FR-104**: 主会话用户 MUST 能够取消运行中的子代理：取消后子代理回合被收口（镜像无孤儿回合），已发生的 usage 仍入账。
- **FR-105**: mulix MUST 提供记忆服务：本地记忆条目的增删查（引擎经 memory_* MCP 工具）、每回合提交前的检索召回；召回命中以低权限文本块追加在该回合 user message 尾部（不改 system prefix、不改工具面——缓存构造护栏保持）。
- **FR-106**: 记忆服务 MUST 可配置开关（默认关闭）：关闭时零注入、零检索开销，行为与 P1 一致；开启时召回有注入预算上限（按相关性截断）。
- **FR-107**: mulix MUST 支持在项目 mulix.toml 声明外部 MCP server（command 形式）：其工具以 server 名命名空间暴露、注册期冻结（两次启动清单逐字节一致）、复用 P1 权限治理与 usage 记账。
- **FR-108**: 外部 MCP 工具调用 MUST 有超时上限（默认 60 秒，可按 server 覆盖）：超时以错误收口；server 进程崩溃不影响 mulix 主进程与其他工具（明确错误 + 告警留痕）。
- **FR-109**: mulix MUST 在会话运行中检测项目指令文件（CLAUDE.md/AGENTS.md）的变更并发布提醒事件（不重载快照、不中断会话）；提供管理命令输出当前生效的指令快照（来源与摘要）。
- **FR-110**: 分层检查工具 MUST 校验：包分层导入规则（§5.3）、文件职责棘轮、动态内容注入点唯一（turn tail）——违规以非零退出码失败并列出位置，可在 CI 中作为独立步骤执行。
- **FR-111**: mulix MUST 支持用户自定义钩子：在 mulix.toml 声明钩子时点（P1 四时点内）与可执行脚本，启动期校验声明（非法声明拒绝启动）；脚本经 stdin 收事件 JSON，其输出/退出码按钩子语义生效并入审计镜像。
- **FR-112**: 自定义钩子执行 MUST 有超时与崩溃隔离：钩子失败不悬挂主流程（按 P1 钩子消费者的既定 fail-open/fail-closed 语义降级 + 告警）。
- **FR-113**: 子代理、记忆、外部 server、自定义钩子产生的全部事件 MUST 遵循 P1 事件红线（先持久化后发布、镜像 1:1 不变量），审计可追溯。

### Key Entities *(include if feature involves data)*

- **子代理会话（Subagent Session）**: 独立镜像 + 会话元数据；属性含父会话引用、委派任务描述、状态（运行中/完成/取消/失败）；与主会话构成委派链（有向无环，深度受限）。
- **记忆条目（Memory Entry）**: 用户/代理明确要求记住的事实或决策；属性含内容文本、来源会话、创建时间、命中统计（可选）；本地持久化，供 BM25 检索。
- **外部 MCP Server**: mulix.toml 声明的外部工具进程；属性含名称（命名空间）、启动命令、超时覆盖；工具面在注册期冻结。
- **自定义钩子声明**: 时点 + 脚本路径 + 超时；启动期校验，运行期事件 JSON 经 stdin 传入。
- **指令快照（Instruction Snapshot）**: 会话启动时 CLAUDE.md/AGENTS.md 的内容快照；会话内不因文件变更而改变（变更仅产生提醒事件）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在真实代码仓库中，一次子代理委派能完成多步编码任务（读写文件、跑测试、提交），结果与 usage 回收进主会话，全程事件可审计——design §11 P2 出口标准 1。
- **SC-002**: 记忆召回开启时相关记忆出现在回合尾部且配置面逐字节不变（护栏测试通过）；关闭时行为与 P1 一致——design §11 P2 出口标准 2（「可开关且不破坏缓存护栏」）。
- **SC-003**: 分层检查工具在 CI 中执行：注入一处分层违规即可复现非零退出与位置报告——design §11 P2 出口标准 3（「分层违规 CI 阻断」）。
- **SC-004**: 外部 MCP server 的工具可在回合中成功调用；超时与 server 崩溃两场景均不悬挂主流程（各有测试钉死）。
- **SC-005**: 会话中修改 CLAUDE.md 产生提醒事件且会话继续使用启动快照（快照语义与 P1 一致）。
- **SC-006**: 全部新事件类型（委派链、召回注入、外部工具、自定义钩子）在镜像中可审计且保持 1:1 不变量（崩溃恢复测试覆盖子代理会话）。

## Assumptions

- 记忆检索为本地 BM25（无外部向量库依赖）；召回注入预算默认上限 2000 字符/回合（可项目覆盖）。
- 子代理与主代理共用同一引擎二进制与 engine.lock 版本策略；子代理会话继承父会话的工作区。
- 外部 MCP server 采用 stdio 传输（P2 不含 HTTP/SSE 远程 server）。
- 自定义钩子的 P1 四时点（SessionStart/PreToolUse/PostToolUse/Stop）不扩张；新时点属后续阶段。
- CLAUDE.md 管理命令以「查看快照 + 触发重读提醒」为界；编辑指令文件仍由用户自己的工具完成（mulix 不做编辑器）。
- P1 遗留的复审 minor（N2/N4/N5）与本阶段工程一起修复，不单独立 change。

## Out of Scope

- HTTP/SSE 传输的远程 MCP server（P4 多入口范围）。
- 语义向量检索 / 嵌入模型（BM25 之外的召回算法）。
- 子代理并行 fleet 调度与 worktree 隔离（P5 高级范围）。
- 真实 CLI nightly 基准与预算控制（P3 治理完备范围）。
- 自定义钩子的新时点扩张与远程钩子执行。
