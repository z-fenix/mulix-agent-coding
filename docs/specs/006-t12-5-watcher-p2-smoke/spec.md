# Feature Specification: T12-5 watcher 真实会话复测与 P2 冒烟记录修正

## 背景(问题陈述)

P2 冒烟 C(真实引擎 2.1.296)验证了指令文件快照语义(会话用启动快照、文件变更不中断会话),但 **watcher 提醒未出现**——当时以「turn 14.7s 短于 watcher 生效窗口」解释并路由复测。P2 验收复核发现**原解释与时间线矛盾**:复检显示编辑时刻早于引擎收到消息约 30 秒(引擎启动耗时),按 2s 轮询节拍 watcher 本应命中多次。机制自此未定论:

- **H1(基线时序)**:watcher 基线在 start 序列尾装载(引擎 init 之后)——若编辑发生在基线装载**之前**,快照捕获的已是编辑后内容,无 delta 可报。这是 P1 既有语义(「启动时无文件即无快照」的同族:基线即启动时点观测),**不是缺陷**——但意味着 P2 冒烟 C 的编辑时点根本不构成有效复测。
- **H2(接线缺陷)**:watcher 发布的 notice 未达 stdout/镜像。
- **H3(轮询未运行)**:会话存活期 ticker 未工作。

机制面由 6 个矩阵测试钉死(`TestWatchInstructions*` 全 PASS),单测无法裁决的是**真实引擎装配路径上的时序**。复测条件(P3① 重钉:pin=2.1.296=本机实测)已由 003-p3-2-1-296 满足。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 真实会话 watcher 复测定论 (Priority: P1)

在真实引擎会话(2.1.296,pin 一致)中,以**基线确立之后**的编辑时点重新测试 watcher 提醒:完整记录时间线(引擎启动/init 完成时刻、编辑落盘时刻、notice 观测时刻),给出机制定论——三选一:

1. **notice 出现**:机制健康,P2 原解释(窗口短)不成立但无缺陷——原冒烟属编辑时点无效;
2. **notice 未出现且时间线证明应命中**:真实缺陷(H2/H3)→ 如实记录并路由修复(修复不在本变更内);
3. **notice 未出现且属基线时序类**(H1):确认 P1 快照语义的正确行为,给出「有效复测的编辑时点」判定标准。

**Why this priority**: 机制定论是本变更的全部价值;时间线证据是定论的唯一合法依据。

**Independent Test**: 独立 git 工作区 + 真实引擎 + `mulix run` 长回合(引擎被指派耗时任务,保证回合存活覆盖基线确立后的编辑窗口),编辑 CLAUDE.md,观测 stdout/镜像中的 notice;时间线三时刻(基线装载/编辑落盘/notice 观测)从镜像事件与文件 mtime 如实提取。

**Acceptance Scenarios**:

1. **Given** 真实会话启动且 watcher 基线已确立(引擎 init 完成), **When** 会话存活期内编辑指令文件内容, **Then** 复测产出一个明确的机制定论(上述三选一),时间线证据落档。
2. **Given** 复测定论为缺陷(H2/H3), **When** 记录, **Then** 缺陷路由后续变更,本变更不冒充修复。
3. **Given** 复测定论为无缺陷(H1 或 notice 出现), **When** 记录, **Then** P2 冒烟 C 的原解释被按证据修正/补强。

### User Story 2 - P2 冒烟记录按事实修正 (Priority: P2)

`docs/evidence/p2-smoke.md` 的相关记录按复测结论修正:冒烟 C 的 watcher 段落追记复测结论与证据指针;诚实限制清单中受影响条目(含 #3「同基线 A/B 对照不可做」——003 重钉后本机=pinned 2.1.296,该限制的前提已变化)按事实核对并更新,不改写历史结论、只追加事实修正(与 003 关闭 P2 限制 #1 的追加式修正同一惯例)。

**Why this priority**: 记录修正是复测价值的落档;依赖 US1 结论。

**Independent Test**: p2-smoke.md 中不再存在与复测结论矛盾的未修正陈述;修正均为追加式(原文保留);报告/台账可追溯。

**Acceptance Scenarios**:

1. **Given** 复测结论已定, **When** 修正 p2-smoke.md, **Then** 冒烟 C 追记复测结论 + 证据指针;诚实限制 #3 按事实更新(003 后同基线对照的前提变化如实记录)。
2. **Given** 全部修正如实追加, **When** 复核, **Then** 无历史结论被改写;P2 台账路由项 ④ 可标记完成。

## Edge Cases

- 长回合无法保证(引擎任务提前完成)时怎么办?——编辑时点以「引擎 init 完成 + 基线装载」为锚(镜像 init 事件时刻),编辑后至少等待 ≥2 个轮询周期(≥4s)再观察;回合过短则如实记录并调整任务时长重试。
- 复测中 notice 出现但**晚于预期**(如 >2 个周期)时怎么办?——如实记录实际时延;时延异常(远超轮询间隔)仍属机制发现,记录之。
- 编辑方式(内容修改 vs 删除)时怎么办?——以内容修改为主测(与 P2 冒烟 C 同型);删除语义已由单测钉死,不重复。
- 复测环境受阻(凭据/网络)时怎么办?——按 FR-108 惯例如实记录未完成原因,路由后续;不得以单测冒充真实复测。
- 修正 p2-smoke.md 时发现其他过时陈述时怎么办?——只修正与本变更结论直接相关的条目(watcher 段 + 限制 #3);其余不动。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-101**: 真实会话复测 MUST 在 pin 一致的引擎(2.1.296)上进行,使用独立 git 工作区与无人值守通道(`mulix run`),方法对齐 P1/P2 冒烟惯例。
- **FR-102**: 编辑时点 MUST 锚定在「watcher 基线装载之后」:以镜像 init 事件时刻为基线锚,编辑落盘时刻晚于该锚;时间线三时刻(init/编辑/notice)MUST 从镜像事件与文件时间戳如实提取,不得估算。
- **FR-103**: 复测 MUST 产出机制定论(H1/H2/H3 三选一),定论 MUST 有时间线证据支撑;证据(命令、输出摘录、镜像事件、时间戳)落 `docs/evidence/p3-watcher-retest.md`。
- **FR-104**: 若定论为真实缺陷,MUST 如实记录并路由后续变更——本变更不实施修复,不得以任何形式冒充修复完成。
- **FR-105**: `p2-smoke.md` 修正 MUST 为追加式(原文保留、事实修正以追记/批注形式),范围限:冒烟 C watcher 段追记 + 诚实限制 #3(及与复测直接相关的限制条目)按事实更新。
- **FR-106**: 本变更 MUST NOT 修改 watcher 或控制器代码——即使定论为缺陷,代码修复路由后续;单测矩阵不新增(6 测已钉,如复测揭示单测缺口,记录之并路由)。
- **FR-107**: 全量门禁 MUST 保持绿(本变更产出为证据与文档,代码零改动是验收的一部分)。

## Key Entities *(include if feature involves data)*

- **时间线(Timeline)**: 三时刻——基线装载(镜像 init 事件)、编辑落盘(文件 mtime)、notice 观测(stdout/镜像事件);机制定论的依据。
- **复测证据(Retest Evidence)**: 独立工作区说明、引擎版本、任务文本、命令与输出摘录、镜像事件摘录、时间线;独立于自动化门禁归档。
- **记录修正(Record Amendment)**: p2-smoke.md 的追加式修正;原文保留。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 复测完成且机制定论明确(H1/H2/H3 三选一),时间线三时刻有据可查。
- **SC-002**: p2-smoke.md 修正完成:冒烟 C 追记 + 限制 #3 按事实更新,追加式、无历史改写。
- **SC-003**: P2 台账路由项 ④(T12-⑤)可关闭;若定论为缺陷,缺陷已入路由清单且本变更如实标注「未修复」。
- **SC-004**: 全量门禁绿、代码零改动(除证据文档与 p2-smoke.md 修正外无文件变更)。

## Assumptions

- watcher 轮询间隔 2s、基线在 start 序列尾装载(引擎 init 之后)为现状事实(代码已核),复测以此设计编辑时点。
- 无人值守长回合可经指派耗时任务(如经 allow 清单的 shell sleep)保证存活窗口;引擎任务编排细节归执行。
- p2-smoke.md 限制 #3 的「修正」指按 003 后的事实(pinned=2.1.296=本机)更新其前提陈述;P1 冒烟 A/B 方法的可行性结论随事实记录,不预设。
- 若复测揭示单测矩阵缺口(如「基线后编辑」场景未被矩阵覆盖——矩阵 6 测似未含「init 后才编辑」的真实装配时序),如实记录并路由,不在本变更补测。

## Out of Scope

- watcher/控制器代码修复(即使定论为缺陷)、T8-② 启动后新建文件监控(产品裁定)、轮询间隔/策略调整。
- P3 路由其余项:⑤ T12-⑥ SC-006 计数、⑥⑦⑧⑨ 各项及廉价测试补强批次(累积 deferred minors)。
- p2-smoke.md 中与 watcher/限制 #3 无关的条目。
