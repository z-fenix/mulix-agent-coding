## User Scenarios & Testing *(mandatory)*

### User Story 1 - 使用明确锁定的新引擎版本 (Priority: P1)

作为项目维护者，我希望项目将 Claude CLI 2.1.301 作为本次受测目标，同时继续拒绝未明确放行的版本漂移，避免更新界面功能时失去原有启动治理。

**Why this priority**: mods 接缝与引擎版本相关；升级必须有独立证据，不能把本机存在新版等同于项目已完成兼容性验证。

**Independent Test**: 检查项目版本锁、匹配与不匹配版本的启动结果，以及本次版本验证记录；旧测量记录保持可追溯。

**Acceptance Scenarios**:

1. **Given** 项目原锁定版本为 2.1.296，**When** 本变更完成，**Then** 版本锁指向 2.1.301，记录实际更新日期，保留既有协议识别约定。
2. **Given** 实际引擎版本与锁定值不一致且没有显式漂移放行，**When** 经产品入口启动，**Then** 启动继续被拒绝，不为通过新功能验证而默认放行。
3. **Given** 历史缓存基线或总纲配对记录使用旧版本，**When** 查看本次升级证据，**Then** 能区分历史数据与 2.1.301 的新验证；不得重写旧证据或冒称已重新测得相同缓存表现。

---

### User Story 2 - 在原生会话中只读查看工作流状态 (Priority: P1)

作为在本仓库工作的使用者，我希望在 Claude Code 原生界面中主动打开工作台，查看当前变更、阶段、审批与验证状态，并获得明确的只读查询入口，而不因打开面板改变工作流或执行任务。

**Why this priority**: 这是首批 mods 交付的独立价值；它提供可见性，不将显示层升级偷偷变成执行权或审批权变更。

**Independent Test**: 在含有效工作流状态的测试仓库中打开工作台并刷新，随后比较产品数据、工作流文件与批准标记；查询前后应保持不变。

**Acceptance Scenarios**:

1. **Given** 当前仓库有 active change，**When** 用户打开状态视图，**Then** 可见仓库身份、change、phase、设计批准状态及验证结果；缺失字段不会被补成已批准或已通过。
2. **Given** 状态由另一会话合法更新，**When** 用户刷新视图，**Then** 显示新的状态；读取失败时明确标记不可用或过期，不把旧快照当作最新结果。
3. **Given** 无 active change、工作流工具不可用或状态损坏，**When** 用户查询，**Then** 得到具体的非成功状态，不自动创建变更、初始化仓库或修复文件。
4. **Given** 用户使用只读工作台入口，**When** 打开、刷新或关闭视图，**Then** 不提交模型任务、不改变 active、不转换阶段、不设置批准标记，也不覆盖原有原生命令。

### User Story 3 - 看懂缓存与用量的来源及统计窗口 (Priority: P2)

作为使用者，我希望查看上下文占用、可得的回合 token 分类、缓存命中率和估算费用，并明确知道这些数字属于哪个会话、来自哪个提供方、覆盖哪个观察窗口，避免把不同账本的数据混为一谈。

**Why this priority**: 用量可见性有价值，但错误的会话归属、重复累计和不明窗口会产生比缺失数据更严重的误导。

**Independent Test**: 输入已知分类计数与重复通知，核对展示、加权汇总及数据归属；无数据和零输入场景不得显示伪造的正常统计。

**Acceptance Scenarios**:

1. **Given** 当前原生会话提供可用用量，**When** 用户查看用量视图，**Then** 显示会话身份与数据来源，区分未缓存输入、缓存写入、缓存读取及输出；上下文占用与回合累计不是同一个指标。
2. **Given** 先后观察到多回合不同输入规模的数据，**When** 显示观察窗口内累计命中率，**Then** 按缓存读取总量除以总输入计算，不使用逐回合百分比的算术平均；同一回合重复到达不会重复累计。
3. **Given** 工作台在会话中途启用、重载，或某回合没有用量，**When** 展示统计，**Then** 明确区分整个原生会话已有状态与工作台实际观察到的回合窗口，不伪造启用前历史，也不把缺失值当成零。
4. **Given** 总输入为零或定价信息不可得，**When** 展示命中率或费用，**Then** 标记不可计算或不可得；费用始终标为估算，不称为供应商精确账单。

### Edge Cases

- 已安装版本、当前运行会话版本与项目锁定值不同，不能仅凭其中任意一个值宣布全部兼容。
- 项目版本锁或工作流状态缺失、损坏、读取失败时，不自动改写、补默认成功值或放宽版本治理。
- 用户切换仓库或 active change 后，旧视图不能继续冒充新目标状态。
- 无绘制表面、终端空间不足或用户未启用 mod 时，不宣称面板已显示，不自动修改配置或窃取输入焦点。
- 原生命令名称发生冲突时，不覆盖引擎内建功能或让查询入口意外执行原生命令。
- 用户中断查询、关闭视图或卸载 mod 后，迟到结果不能恢复已关闭界面或改写新的查询目标。
- 压缩、子代理、直接模型调用等计费活动可能具有不同统计口径；来源不明时不得归入本工作台已观察主回合的累计值。
- 模型及工具输出、仓库路径和状态文本均视为数据，不得作为待执行指令；展示须避免控制字符造成的终端误导。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 项目 MUST 将本次目标引擎版本锁定为 2.1.301，记录实际更新日期，并保留现有初始化版本识别约定与默认漂移拒绝行为。
- **FR-002**: 升级 MUST 保留旧版本与旧缓存测量的历史来源。沿用历史参考值时 MUST 明示它不是本次新版本测量；总纲的旧配对基线不随本变更自动改写。
- **FR-003**: 工作台 MUST 作为用户可主动使用的 Claude Code 原生只读伴随界面交付，提供工作流状态、用量查看及刷新入口；不得覆盖原生命令。
- **FR-004**: 状态视图 MUST 标明所查询仓库、change、phase、设计批准和验证结果；无 active、缺失字段、未知状态及查询失败 MUST 显式呈现，不推断成功。
- **FR-005**: 用户刷新后 MUST 能看到读取时的最新状态；保留上次结果时 MUST 标记过期和失败原因，不静默冒充当前状态。
- **FR-006**: 工作台运行时 MUST NOT 修改产品数据或工作流文件、切换 active、推进阶段、记录批准、改写版本锁、变更权限、创建或取消任务、压缩或清理会话。界面自身的宿主管理状态不构成产品写入授权。
- **FR-007**: 只读展示 MUST NOT 注入或修改模型提示词，不自动发起模型请求、额外 token 计数请求或外部网络上报；不得读取或显示凭据。
- **FR-008**: 用量视图 MUST 标明会话身份、提供方、数据来源与统计窗口，区分原生会话整体状态和工作台实际观察窗口，不将原生会话标识自动当作 mulix 产品会话标识。
- **FR-009**: 可得回合用量 MUST 分别展示未缓存输入、缓存写入、缓存读取和输出。缓存命中率 MUST 使用 `缓存读取 / (未缓存输入 + 缓存写入 + 缓存读取)`；跨回合累计 MUST 按 token 加权，并避免重复累计。
- **FR-010**: 缺失数据、零分母、无定价及中途启用 MUST 显式区分。费用 MUST 保留估算属性，不伪造历史、零值、精确账单或新版本性能结论。
- **FR-011**: 首批缓存用量 MUST 仅展示当前原生 Claude Code 会话的数据，明确标注来源与观察窗口；不查询 mulix 产品会话账本，不合并其他会话的计数，不将原生会话用量宣称为 mulix 产品会话账本。
- **FR-012**: 查询、重载、中断及关闭 MUST 不造成未授权后台执行、重复统计、迟到结果错配或自动重开界面；失败只影响工作台可用性，不改变产品的治理裁决。
- **FR-013**: 使用者 MUST 能从交付说明区分原生交互环境与既有 mulix 托管执行入口。没有可绘制界面的托管会话 MUST NOT 因 mod 加载成功就被标记为已显示原生面板；本变更不替换既有 Go TUI 或审计路径。
- **FR-014**: 镜像先持久化后发布、单写路径、1:1 审计、权限拒绝优先级、无人值守 fail-closed、工具冻结及既有插件生命周期契约 MUST 保持不变；只读工作台不能成为第二权威或替代治理层。
- **FR-015**: 自动化验证与真实验证 MUST 分别记录。引擎升级与原生工作台的真实证据 MUST 标明版本、环境、入口、操作、结果和限制；用户未启用、环境不支持或验证受阻 MUST 记录为未通过该真实场景，不以模拟测试冒充。
- **FR-016**: 本变更 MUST 可单独追踪、验收和停用；停用工作台后既有产品执行与审计仍可使用。本变更的批准或完成 MUST NOT 自动推进总纲或后续权限、记忆、子代理适配。

### Key Entities *(include if feature involves data)*

- **版本基线**: 项目锁定值、实际运行版本、更新日期、历史参考及本次验证结果。
- **工作流快照**: 仓库身份、change、phase、批准状态、验证结果、观察时刻和可用性。
- **会话用量视图**: 会话身份、提供方、分类计数、上下文占用、估算费用、观察窗口及缺失原因；不同来源不自动合并。
- **交付证据**: 独立 change、覆盖需求、入口、版本、测试与真实验证结果、限制及阻塞。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 项目锁定值为 2.1.301；匹配与不匹配版本的验证覆盖通过，默认漂移拒绝不变，历史基线的来源无丢失或伪造。
- **SC-002**: 有 active、无 active、缺失字段、损坏状态及查询失败均有可判定结果；没有任何缺失或错误状态被显示为已批准、已通过或正常零值。
- **SC-003**: 用户在一个已启用的受支持原生会话中，可通过明确入口打开状态与用量视图并刷新，无需手工编辑项目状态或原生配置文件。
- **SC-004**: 已知用量样本的分类计数、加权命中率及去重全部正确；零输入、缺失定价和中途启用均正确披露来源与窗口。
- **SC-005**: 正常查询、错误查询、刷新、重载、中断与关闭的验证中，产品/工作流数据修改、任务提交、审批变化及权限放宽均为零；已有执行与审计回归不退化。
- **SC-006**: 验证记录明确区分自动化通过、真实通过和阻塞；不存在把仅原生界面演示、单独版本查询或 mod 加载成功当作全产品等价验收的记录。

- 2026-10-15 历史查询的本机版本为 2.1.300；2026-10-16 已复核当前 CLI 为 2.1.301，用户明确将目标更新为该版本。本变更前项目锁为 2.1.296，本次锁定目标是 2.1.301；不将本机安装、锁文件更新或历史命中率当作完整新版本验收。
- 用户已批准创建独立变更、首批范围和 A，随后明确批准规格、2.1.301 目标修订、书面设计及任务。最新 /goal 指定在主分支实施且不建分支；提交、安装、热加载及验证的实际边界按下方新裁定和执行台账记录。归档与推送未获本次授权。
- 首批界面以当前 Windows 上的原生 Claude Code 终端会话为真实验收对象；没有相应证据前不承诺其他绘制表面或平台等价。
- 现有产品使用托管协议会话，不能假定原生面板自然出现在既有 Go TUI 内。原生伴随工作台与产品入口分别标记验收结果。
- 首批保持只读，不移交权限、记忆、子代理或审计权威；工作台展示的下一步信息不是执行或批准动作。
- 不默认增加产品第三方依赖、修改原生全局配置、安装远程软件、对外分享代码或执行新增付费实验；需要时另行获得对应授权。

## Out of Scope

- 权限拦截、审批授权、记忆召回与存储、子代理创建/取消及模型路由的 mods 改造。
- 替换 Go 宿主、Go TUI、镜像恢复路径、NATS 总线、注册表或 kernel 生命周期。
- 通过界面执行阶段转换、审批、会话提交、缓存清理、自动压缩、插件市场发布或自动安装。
- 查询 mulix 产品会话账本、展示其他会话用量，或合并原生会话与产品账本的计数。
- 将观察式审计视图升级为权威镜像，将原生会话与 mulix 产品会话无条件认作同一个会话。
- 修改总纲的历史配对基线，批准总纲设计，或宣称完整 dsh 等价目标已交付。
- 在本规格及后续设计、任务获批之前更新版本锁、编写产品代码或测试。
