# Feature Specification: T5-1 超大行隔离为损坏段

**Change**: `005-t5-1`

**Created**: 2026-10-11

**Status**: Draft

**Input**: User description: "P3 路由③ T5-①:超过 16MB 的行导致的硬失败 → 隔离为损坏段"——P2 复审路由项,可靠性 hardening。

## 背景(问题陈述)

JSONL 逐行读取面对单行设有 16MB 大小上限(防护性设计:单个事件不应这么大)。现状下,一旦文件中出现超过上限的行(异常来源:失控的工具输出回流、磁盘/驱动异常导致的粘连写入),读取器立即整体报错——**整份文件不可读**,进而:

- 会话镜像加载硬失败(用户无法打开会话);
- 崩溃恢复路径硬失败(无法救援任何已完成的行);
- 记忆库读取硬失败(全部记忆不可用)。

一条坏行拖垮全部好行,违反「损坏隔离」的既有精神——文件尾部半行(崩溃残留)早已按「损坏段如实上报、好行照常读取」处置,超限行却享受不到同等待遇。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 单条超大行不再拖垮整份文件 (Priority: P1)

会话镜像/事件/记忆文件中出现一条超过大小上限的行。读取面把该行隔离为损坏段:其余全部完整行正常读取、逐行可解码、下游功能(镜像加载、崩溃恢复、记忆召回)照常工作;损坏事实如实可见(计数/标记,不静默丢弃),调用方按既有损坏处置路径接管(隔离区转储/告警/修复)。

**Why this priority**: 「一条坏行拖垮全会话」是本缺陷的全部后果;读取面隔离即关闭后果,独立可交付。

**Independent Test**: 构造含一条超限行的 JSONL(超限行前后均有正常行):读取返回全部正常行 + 损坏标记,超限行不计入完整行;不含超限行的同文件行为与现状逐字节一致。

**Acceptance Scenarios**:

1. **Given** 文件含「正常行—超限行—正常行」, **When** 读取, **Then** 两条正常行完整返回,超限行被隔离为损坏段并如实标记,无错误返回。
2. **Given** 文件仅含正常行(含尾部半行场景), **When** 读取, **Then** 行为与现状逐字节一致(无回归)。
3. **Given** 消费方(镜像加载/崩溃恢复/记忆)读到含损坏段的读取结果, **When** 各自按既有损坏处置路径处理, **Then** 处置行为与既有「损坏尾部」路径同构(隔离/告警/硬错的既有语义不变),不新增静默丢弃。

### Edge Cases

- 超限行恰为文件最后一行(无换行结尾)时怎么办?——按损坏段隔离(与尾部半行判定并存,不重复计数)。
- 文件含**多条**超限行时怎么办?——各自隔离,损坏计数如实累加;正常行全部照读。
- 超限行后紧跟正常行时怎么办?——正常行必须可读(隔离不得吞掉后续内容)。
- 损坏段的内容是否转储(如隔离区文件)时怎么办?——超限段可能本身巨大(>16MB),转储策略(全量/截断+元信息)与磁盘占用上限归设计;要求:损坏事实可审计、不得无界占用磁盘。
- 大小上限值本身是否调整时怎么办?——上限保持现值(防护性设计,单事件协议面);本变更只改「超限后的处置」,不改「上限的数值」。
- 损坏段计数与既有「尾部半行」标记同时存在时怎么办?——两类损坏分别如实呈现,调用方可区分来源;合并展示形式归设计。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-101**: JSONL 读取面遇到超过大小上限的单行时,MUST NOT 返回整体错误:该行 MUST 被隔离为损坏段,其余完整行正常读取返回。
- **FR-102**: 超限行隔离后,MUST NOT 吞掉文件中后续内容:后续正常行照常可读。
- **FR-103**: 损坏段 MUST 如实呈现(计数/标记),MUST NOT 被静默丢弃;呈现形式 MUST 让调用方可区分「尾部半行」与「超限行」两类来源。
- **FR-104**: 消费方(镜像加载、崩溃恢复、记忆库)的既有损坏处置语义 MUST 保持:各自对损坏的既有反应(隔离区转储/告警/权威加载硬错)不因本变更改变;超限段经由既有损坏处置路径流转。
- **FR-105**: 无超限行文件(含既有尾部半行场景)的读取行为 MUST 与现状一致(无回归);大小上限数值 MUST 不变。
- **FR-106**: 损坏段的磁盘足迹 MUST 有界:隔离转储(若有)不得无界占用磁盘;策略归设计,上限须存在。
- **FR-107**: 写入面与既有「先持久化后发布」「1:1 镜像」红线 MUST 不受影响(本变更只动读取面的损坏处置)。

### Key Entities *(include if feature involves data)*

- **损坏段(Damaged Segment)**: 读取面无法作为完整行交付的字节区间;两类来源:尾部半行(崩溃残留,既有)、超限行(本变更新增);属性:字节内容(或其有界转储)、来源、在文件中的序位。
- **大小上限(Line Cap)**: 单行字节上限(现值 16MB,防护性);超限即损坏段,不改数值。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 含超限行的文件(超限行前后均有正常行)读取:全部正常行返回、超限行隔离、损坏计数如实、无整体错误。
- **SC-002**: 无超限行文件的全部既有读取行为(含尾部半行)与现状一致;既有全量测试零回归。
- **SC-003**: 三类消费方(镜像加载/崩溃恢复/记忆)对含超限行文件的行为:各自既有损坏处置语义不变,且不再因超限行整体硬失败(其中权威加载按其既有「损坏即硬错」语义处置,属 FR-104 的保持而非缺陷)。
- **SC-004**: 多条超限行场景:计数如实累加,后续正常行不受影响。

## Assumptions

- 大小上限 16MB 保持不变;超限即视为异常数据(防护性设计的一部分),本变更只改处置不改阈值。
- 读取面是修复位置(单点修复,三个消费方同时受益);写入面无超限行写入路径需要变更(写入侧单行均远小于上限)。
- 损坏段的隔离转储复用既有损坏处置基础设施(隔离区文件/损坏段结构),不新建平行机制;具体转储形状(全量/截断+元信息)归设计。
- 权威加载路径(sessionx 加载)对损坏的「硬错 + 由恢复路径处置」语义属既有治理设计,本变更保持(用户经恢复流程救援)。

## Out of Scope

- P3 路由其余项:T12-⑤ watcher 复测、T12-⑥ SC-006 计数、T10-①②、T5-⑤ fsync、T8-①② 及廉价测试补强清单。
- 累积 deferred minors 批次(003 两条 + 004 三条)——随廉价测试补强一并处理。
- 大小上限数值调整、写入面变更、行内容压缩/分块等存储格式演进。
