> 参考材料（本目录下）：`survey-reasonix-tui.md`（目标形态全貌）、`survey-mulix-tui.md`（现状基线与硬约束）。
> 定位：mulix 的 TUI 从「尾部截断的单行 inline 界面」重构为参考实现的「全屏接管 + 语义保留转写」形态；治理三层（权限/缓存/镜像）语义完全不变，TUI 只是更好的呈现面。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 全屏转写区：可滚动、可跟随的回合实况 (Priority: P1)

用户启动 mulix-cli 进入 TUI 后，整个终端窗口被接管：上方是完整会话转写区（历史 + 实时），下方固定输入区与状态栏。回合进行中，助手文本流式上屏（按完整段落提交，半开代码围栏不提前渲染）；思考内容以有界尾部窗口展示，回合结束后折叠为「已思考 Ns」样式块；工具调用以卡片形式可见（动词 + 主参数、运行状态、有界输出尾部、失败显著标红）。用户可 PgUp/PgDn/滚轮上翻历史，新内容到达时若在底部则自动跟随，上翻后不被强制拉回；窗口缩放后转写按语义重排并尽量保持阅读位置。运行中回合可按 Esc 取消（现在只能整体退出程序）。

**Why this priority**: 现状 TUI 无滚动、无工具/思考/回合起始渲染、无缩放重排、不能取消回合——「看不清引擎在做什么、也停不下来」是最大缺口。本故事独立交付即可让 TUI 从「能跑」变为「能观察、能干预」。

**Independent Test**: ConPTY 真机驱动一个含工具调用的完整回合（方法沿用 docs/evidence/smoke-tui-2026-10-15.md），断言：工具卡片出现且状态流转、流式段落逐步上屏、上翻后新输出不拉回、回底后恢复跟随、Esc 取消生效、缩放后重排不丢内容。

**Acceptance Scenarios**:

1. **Given** 空会话，**When** 提交一个会调用工具的任务，**Then** 转写区依次出现工具卡片（动词 + 主参数）、有界输出尾部、回合完成行；行数超过视口高度时不丢内容，可滚动回看。
2. **Given** 回合进行中用户已上翻，**When** 新输出到达，**Then** 视图保持用户位置；**When** 用户回到底部，**Then** 恢复自动跟随。
3. **Given** 回合进行中，**When** 按 Esc，**Then** 运行中回合被取消且取消状态可见，程序不退出。
4. **Given** 调整窗口尺寸，**When** 重排完成，**Then** 转写按新宽度重新换行、样式序列无残缺、阅读位置尽量保持。

### User Story 2 - 输入体验：多行编辑、历史召回、粘贴折叠、补全 (Priority: P2)

输入区从单行升级为多行编辑器：随内容 1→N 行自适应（有上限）；↑/↓ 召回已提交历史且保留当前草稿；大段粘贴折叠为可删除的标记，提交时还原全文；Alt+Enter/Ctrl+J 换行；词级编辑（Ctrl+Backspace 等）。输入 `/` 弹出斜杠命令补全菜单（↑/↓/Tab/Enter/Esc 键盘导航）；`/resume` 提供交互式会话选择器（列出可用镜像会话，替代现在的手工输 id）。

**Why this priority**: 输入是使用频率最高的界面；现状单行无召回，粘贴长文本几乎不可用，/resume 无选择器。

**Independent Test**: 状态机单测以键盘消息序列驱动编辑器（召回/折叠/换行/补全导航/会话选择器），另加 ConPTY 真机冒烟覆盖粘贴与召回的真实输入路径。

**Acceptance Scenarios**:

1. **Given** 已提交多条输入，**When** 连按 ↑，**Then** 依次召回历史且当前草稿保留，↓ 可返回草稿。
2. **Given** 粘贴超过阈值的文本，**When** 进入编辑器，**Then** 折叠为单个可删除标记；删除标记即移除全部粘贴内容，提交时还原全文。
3. **Given** 输入 `/`，**When** 菜单出现，**Then** ↑/↓ 选择、Enter 补全、Esc 关闭；未知命令仍给出可用列表。

### User Story 3 - 治理呈现与状态升级 (Priority: P2)

授权卡展示工具名 + 参数摘要，键位对齐参考实现（允许一次 / 本会话允许 / 拒绝，数字或字母皆可），现行治理语义原样保留（独占冻结、120s 超时 fail-closed、审批桥、镜像先行）。状态栏升级为双行：模式与状态提示居左、模型与会话遥测居右；每回合完成后在答案下方展示用量回执（输入/缓存/输出 token、成本、命中率）；上下文余量以仪表呈现。

**Why this priority**: 治理是 mulix 的差异化面，呈现质量直接影响裁决效率；用量回执与上下文仪表让「何时压实」可预判。

**Independent Test**: 单测断言授权卡渲染（含参数摘要截断）与键位映射、回执内容来自 Usage 事件、状态栏字段完整；真机冒烟断言 fail-closed 超时路径行为不变。

**Acceptance Scenarios**:

1. **Given** 引擎请求工具授权，**When** 授权卡出现，**Then** 显示工具名与参数摘要；按 n/Esc 拒绝、y 允许一次、a 本会话允许，效果与现 a/s/d 一致。
2. **Given** 一回合完成，**When** 回执渲染，**Then** 显示该回合 token 明细与成本，累计命中率在状态栏可见。
3. **Given** 授权卡等待超时，**When** 120s 到点，**Then** 沿用现行 fail-closed 拒绝语义，无静默放行。

---

### User Story 4 - 观感与输出保真 (Priority: P3)

主题系统（暗/亮底色与强调色，NO_COLOR 与无色彩终端退避）；Markdown 保真渲染（代码围栏、表格、列表）；diff 类工具结果带语法高亮渲染；Ctrl+O 展开完整思考；Ctrl+B 展开被折叠的工具输出；转写区文本选择与复制（OSC 52 退避）。

**Why this priority**: 锦上添花层，依赖 FR-017 的依赖裁定（markdown/高亮库）；不阻塞前三层。

**Independent Test**: 单测覆盖主题回退与渲染保真（表驱动）；真机冒烟确认暗/亮切换与 NO_COLOR。

**Acceptance Scenarios**:

1. **Given** NO_COLOR 环境，**When** 启动 TUI，**Then** 无色彩退避渲染，功能不受影响。
2. **Given** 工具结果含 diff，**When** 渲染，**Then** 行号与语法高亮可见、增删行可辨。

---

### Edge Cases

- 引擎中途退出：转写显示退出原因，程序不崩溃、不静默（现状已有，须在 alt-screen 形态下保持）。
- 事件洪峰（channel 积压逼近 1024）：保持「可慢不可丢」——消费端合并渲染，不丢弃、不阻塞镜像写入；换绑时积压语义仍为「延迟」而非「丢失」。
- 流式中半开代码围栏、超长行、CJK 宽字符：不渲染半段围栏；换行不撕裂样式；宽度计算正确（本机为 Windows/CJK 环境，这是常态而非边缘）。
- ConPTY 输入吞键怪癖（证据文档记录的 5–15s 窗口）：TUI 不因输入抖动进入坏状态。
- Esc/Ctrl+C 语义阶梯：未发送撤回 → 取消回合 → 清空输入 / 双击退出，各态无歧义；授权卡独占时按键不泄漏到编辑器。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: TUI MUST 以全屏（alt-screen）形态接管终端：上方转写视口 + 下方固定区（输入编辑器 + 状态栏），替换现行 inline 尾部截断渲染。
- **FR-002**: 转写区 MUST 支持滚动回看（键盘 + 鼠标滚轮）与「尾部跟随」模式：用户上翻时不被新内容拉回，回到底部后恢复跟随。
- **FR-003**: 助手文本 MUST 流式渲染，且仅按「完整段落」提交上屏（未闭合代码围栏不提前渲染）。
- **FR-004**: 思考内容 MUST 渲染为有界尾部窗口（防刷屏），回合结束后折叠为「已思考 Ns」样式块，可按键展开全文。
- **FR-005**: 每个工具调用 MUST 渲染为工具卡片：动词 + 主参数、运行/完成/失败状态、有界输出尾部（可按键展开、有上限）；失败卡片显著标红并含失败详情。
- **FR-006**: 窗口尺寸变化 MUST 触发转写语义重排（基于各块原始内容重新换行，而非简单截断），并保持阅读位置/跟随状态。
- **FR-007**: 编辑器 MUST 支持多行输入（行数自适应、有上限）、↑/↓ 历史召回（保留草稿）、换行键（Alt+Enter / Ctrl+J）、词级编辑键。
- **FR-008**: 超过阈值的粘贴 MUST 折叠为可删除标记，提交时还原原文。
- **FR-009**: 输入 `/` MUST 弹出命令补全菜单（键盘导航）；`/resume` MUST 提供交互式会话选择器（列出可用镜像会话）。
- **FR-010**: 授权卡 MUST 展示工具名与参数摘要，键位对齐参考实现（允许一次 / 本会话允许 / 拒绝）；现行治理语义（独占冻结、120s 超时 fail-closed、审批桥、镜像先行）MUST 原样保留。
- **FR-011**: 运行中回合 MUST 可被 Esc 取消且取消状态可见；Ctrl+C 退出 MUST 有防误触（双击确认或等价）；Esc/Ctrl+C 语义阶梯 MUST 无歧义。
- **FR-012**: 每回合完成 MUST 展示用量回执（token 明细与成本，来自 Usage 事件）；状态栏 MUST 展示模式、运行状态、模型、命中率与上下文余量仪表。
- **FR-013**: 事件接收 MUST 保持「可慢不可丢」：消费端合并渲染，不丢弃、不因渲染阻塞镜像写入（先镜像后 Sink 红线不变）。
- **FR-014**: 主题与配色：MUST 支持暗/亮底色与强调色，尊重 NO_COLOR 与无色彩终端退避（依赖已按 FR-017 裁定获批）。
- **FR-015**: 界面语言保持中文（不引入多语言目录）。
- **FR-016**: TUI MUST 对 mulix 全部前端可见事件类型有明确渲染语义（含现未渲染的工具调用/结果、思考、回合开始、委托事件），不允许「事件进来无处安放」。
- **FR-017**: 渲染栈第三方依赖按 2026-10-15 用户裁定执行：批准新增 **bubbles v2、goldmark、chroma/v2、go-udiff、clipboard** 五个家族（呈现层专用）；x/ansi、colorprofile、runewidth、uniseg 由间接转直接使用。kernel 与治理层（control/guard/cache/mirror 等）维持零新增第三方。随本变更勘误 CLAUDE.md §4「NATS 唯一例外」条款（第三方依赖改为清单治理；「零第三方」的准确范围是 kernel leaf 级）。
- **FR-018**: 对齐范围按 2026-10-15 用户裁定：**P1–P3 全部纳入本次变更**；三层顺序即实施优先序（P1 最先、P3 最后）。
- **FR-019**: mulix 特有面板 MUST 保留并适配新形态：/agents 子代理面板、/doctor、/cache；/rewind 维持占位（真实透传仍属引擎侧 T32）。Reasonix 独有而 mulix 引擎无对应能力的界面不在本次范围（见 Out of Scope）。

### Key Entities *(include if feature involves data)*

- **转写块（Transcript Block）**: 不可变的已提交内容单元（用户气泡 / 助手段落 / 思考块 / 工具卡 / 回执 / 通知），持有语义原文（原始 markdown、工具名与参数、历史）以支持缩放重排；只追加，仅运行中的块允许原地改写（流式答案块、思考块、运行中工具尾）。
- **编辑器状态**: 多行文本、光标、历史召回栈、粘贴标记、补全菜单状态、忙碌门闩。
- **授权卡**: 待裁决工具请求（工具名、参数摘要、选项集）与决议结果。
- **状态快照**: 周期获取的会话状态（模型、命中率、用量、上下文余量、运行状态）——沿用现行 Snapshot 轮询或改事件驱动，属设计决策。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ConPTY 真机冒烟（方法沿用 docs/evidence/smoke-tui-2026-10-15.md）完成一个含工具调用的完整回合：工具卡片、流式段落、思考折叠、回合回执、状态栏流转全部可见，证据落 docs/evidence/。
- **SC-002**: 现有治理语义测试（TestApprovalExclusiveState、TestApprovalDenyAndSession 等）语义不变且为绿；新增行为（滚动跟随、语义重排、历史召回、粘贴折叠、补全导航、取消回合）均有状态机单测。
- **SC-003**: 每任务 `go test ./... -count=1` 全绿、gofmt 干净、分层 lint 通过；若 TUI 拆新包，layer matrix 先行登记。
- **SC-004**: 渲染覆盖矩阵：mulix 前端可见事件类型 100% 有明确渲染语义（表驱动测试断言）。
- **SC-005**: 真机冒烟中滚动跟随与缩放重排行为正确：上翻不被拉回、回底恢复跟随、重排不丢内容。

## Assumptions

- Bubble Tea v2 / Lipgloss v2 已是既有直接依赖（go.mod 核实，P1 计划批准）；本次在同一框架族内重构，不更换框架。
- 界面语言保持中文。
- Windows 为一等目标（ConPTY / Windows Terminal，conhost 需启用 VT）；不承诺 Termux/Android 原生滚动模式与 SSH 专项优化。
- 治理三层（权限 / 缓存 / 镜像）语义完全不变；审批仍为同步阻塞决议、120s 超时 fail-closed。
- 既有红线不变：先镜像后 Sink、Sink 不可重入、可慢不可丢、分层矩阵（TUI→control 单向）。
- CLAUDE.md §4「NATS 唯一例外」条款过时（与 go.mod 不符），随本变更勘误，勘误本身不改变任何运行时行为。

## Out of Scope

- Reasonix 独有且 mulix 引擎无对应能力的 UI：MCP 管理器、elicit 表单、goals、钱包/余额、lease/takeover、web/desktop 运行时、provider/effort 运行时热切换、压缩卡（mulix 压实机制不同）。
- 多语言目录（en / zh-TW）。
- Termux/Android 原生滚动模式、移动端适配。
- /rewind 真实引擎透传（仍属引擎侧 T32 联调，本次仅保留占位）。
- 引擎侧任何改动（事件词汇、控制器、镜像）——本变更只动前端呈现层；若渲染需要新事件，另行裁定。
