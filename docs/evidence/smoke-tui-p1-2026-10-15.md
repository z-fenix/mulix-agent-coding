## 1. 驱动方法（沿用 smoke-tui-2026-10-15.md 并两项强化）

1. **闭环重发**：每条写键带屏幕谓词（sendUntil：每 10s 重发直至预期效果上屏）；不可观测手势（PgUp/Ctrl+End）按固定节奏重发，离线凭帧断言。
2. **vt10x 帧重建**：ConPTY 输出字节流喂入 vt10x 仿真器，400ms 变帧捕获到 `frames3.log`（逐帧全屏文本+时戳）；原始字节流另存 `raw3.bin`（审计底档）。滚动断言靠「视口顶行内容 + 状态栏 tok 数」而不依赖重建器的滚动条列（vt10x 对 CJK 按 1 列计，与真实终端双列有偏差，帧内右侧偶见上帧残影——重建器伪影，非 TUI 输出）。

**ConPTY 吞键怪癖（本批 7 次运行再证实并量化）**：写入被非确定性吞没；一次有效写入后约 30-36s 内的后续写入被吞、之后恢复可达（run2：33.0s 提交后 56.6s PgUp 被吞、68.6s 落地；run5：32.7s 提交后 63.2/66.2s 被吞、69.2s 落地；run7：33.0s 提交后 41-44.4s 被吞、44.6s 落地）。**每 3-10s 重发是唯一可靠缓解**（与上午冒烟「每 10s 重发」结论一致并加密了节奏）。

**大写字母丢失（新实证）**：输入路径上所有大写字母被吞——「Read」→「ead」、「Chinese」→「hinese」、「Explain」→「xplain」、「Write」→「rite」，7 次运行逐次复现。镜像 assistant_thinking 证实丢字发生在 TUI 上游（conhost VT 输入翻译层）：引擎收到的原文即是「ead」，且模型自行纠正（thinking：`"ead" = "read"`）。非 mulix 缺陷；提交语义不受影响（六/十二文件全部按意图读取）。

## 2. 环境阻塞的发现与排除（FR-108 如实记录）

第一次真机尝试（session `fd655e17…`，已清除）：8 次提交每回合立即失败 **「Not logged in · Please run /login」**。

- **根因**：驱动器进程继承 Claude Code 宿主会话环境——`ANTHROPIC_BASE_URL`、`CLAUDE_CODE_HOST_AUTH_*` 等使嵌套 claude CLI 将鉴权视为宿主托管，不读本机凭据文件。mulix 引擎子进程 env 为整链继承（claudehost.go:148 `cmd.Env = append(os.Environ(), cfg.Env...)`），污染直达引擎。
- **修复**：驱动器启动 ConPTY 子进程前剥除 `CLAUDE*/ANTHROPIC*` 环境变量（driver 侧 scrubEnv）。**mulix 代码零改动**；doctor 复检全绿后引擎正常。
- **结论**：环境污染非 mulix 缺陷；「宿主会话内冒烟」须剥离宿主 env——记为复测注意事项。
