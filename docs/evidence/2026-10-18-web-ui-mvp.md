## 真实引擎受阻事实（FR-108 如实记录）

**模型调用被认证阻塞：**

1. 现象：真实 claude 引擎子进程被 mulix 拉起并完成握手（init 到达、READY、engine_session_id 落镜像），提交回合后引擎流式输出自身错误 `Not logged in · Please run /login`，回合以 `turn_done(is_error=true)` 如实收口——mulix 全栈行为正确，错误未被吞。
2. 直接复现：同 shell 直接运行 `claude -p "回复 ok"` 输出同一句 `Not logged in · Please run /login`（exit 0）——与本冒烟无关的 mulix 侧问题排除。
3. 根因定位：本机 claude CLI 认证由桌面宿主托管——`CLAUDE_CODE_HOST_AUTH_ENV_VAR=ANTHROPIC_AUTH_TOKEN`，而该变量**不在本 shell 环境中**（宿主只向其自Spawn 的引擎子进程注入）。故 mulix（以及任何独立 headless claude 调用）拉起的 claude 均无可用凭证。`C:\Users\Zhang\.claude\.credentials.json` 存在但 headless 直跑仍报未登录。
4. 未尝试交互式 `/login`（需用户交互与账户决定，非 agent 可代行）。

**结论：** 模型回合因环境认证受阻，无法取得「模型真实作答」证据；**未以自动化测试冒充**。作为替代，本冒烟取得了超出回退面（startup + healthz + sessions-list）的证据面：
