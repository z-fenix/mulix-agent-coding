## 1. ConPTY 传输怪癖（本批新量化，全部非 mulix 缺陷）

1. **`\r` → `\r\n` 翻倍**：粘贴体内每个 `\r` 被 conhost 按 CR 语义展开为 CRLF——3 行粘贴体以「5 行」入折叠账（`[粘贴 #1 · 5 行]`）。mulix 按实收字节计行，行为正确；驱动器预期值（3）错在传输层假设。
2. **括号粘贴标记非确定性丢失**：同一序列 6 次重发，前两次标记完整（折叠成功），后四次标记被吞（原文作为普通键入逐字进入编辑器并跨次累积）。
3. **行首字符丢失**（P1 大写丢失的同族）：run2 `/theme ember` 前三次写入行首 `/` 被吞——`theme ember` 作为普通 prompt 进了引擎（became t2，$0.0143）；`reate a file`（c 丢失）同型。
4. **输入再武装窗**（P1 已量化，本批再证）：一次有效写入后约 30–36s 内后续写入被吞，sendUntil 10s 重发为唯一可靠缓解。
5. **大写丢失**（P1 实证）：本批 prompt 全小写规避，未再单列验证。

2. **引擎 PowerShell 工具未过审批回路**（治理观察，非本仓代码缺陷）：run1 t4 中 claude CLI 2.1.300 以自有 PowerShell 工具执行 `echo`，全程未向 `mcp__mulix__permission` 发起审批（镜像无 approval_request，工具直落 tool_result）。mulix 门禁只在引擎询问时被咨询；引擎侧未询问 = 治理旁路。建议作为 watch-item 跟进（引擎工具清单与 permission 覆盖面核对）。
3. **引擎漂移放行留痕**：2.1.300 ≠ pinned 2.1.296，`--allow-engine-drift` 放行，每回合镜像 `notice [engine_drift]` + TUI 留痕——FR-016 设计路径在真机成立。
4. **传输层对驱动器的约束**（§1）：粘贴折叠断言的预期值必须按「conhost 展开后的行数」构造；重发间隔内标记可能丢失。
